# 图数相机（MeasureCam）

工程记录用的水印相机。核心区别只有一句话：**先把现场拍下来，再补录测量数值**，而不是拍之前先把数据填好。

当前版本 **1.9**（versionCode 10）。

## v1.9 相册兼容性

拍照页的“相册”按手机声明的图库入口打开图库主页。如果系统不提供可启动的图库，则使用系统照片选择器或文件选择器，选图后可在应用内查看，返回即可继续拍摄。记录页查看成片时，也可在缺少外部看图程序时使用应用内预览。

## v1.8 导出与现场录入

1. **整包交付。** 在记录页筛选需要的记录，点“导出记录”或“导出筛选结果”，选“照片 + CSV（ZIP）”。包内含记录表和相册成片，CSV 中的照片路径可在解压目录中找到。缺少的照片另列清单。仍可单独导出 CSV。
2. **拖动水印。** 在取景页按住水印拖动，位置随当前模板保存，用于后续拍摄和导入。在“记录 → 修改记录”的照片预览上也可拖动，保存仅更新该张照片。九宫格仍可快速恢复预设位置。
3. **异常值提醒。** 编辑模板时，每个数值字段可设置预警上下限（含端点）。拍后录入逐格对比同字段上一次保存的读数，量值增至 10 倍或降至十分之一会提醒。编辑已有记录时与该记录原值比较。核实后可保存。
4. **桩号推进上限。** 在“编辑模板 → 自动信息”设置单次推进上限，默认 50 米。自动递增启用时，GPS 推算和备用步长都受此限制。手动录入超过上限时需修改，首次桩号用于建立基准。

## v1.7 界面与拍摄优化

- 天气栏只显示天气状况与温度，移除“（预报·MET Norway）”；来源和许可放在设置页。旧记录重新预览/保存时也隐藏该后缀，已经写入像素的旧照片不会自动重写。
- 设置使用分组卡片、实时色块、颜色选择网格与天气开关；模板库突出当前模板，编辑页固定底部保存按钮；记录筛选、数值卡片与空状态统一为浅绿风格。
- 相机界面固定竖向，快门和缩放条始终留在手机同一位置；照片方向单独跟随方向传感器，不再切换拍摄布局。
- 缩放控件增高至 80dp，调整气泡和刻度边距，完整显示倍率。

## 1. 它解决什么问题

今日水印相机改水印的路径是：

```
拍照 → 退出取景 → 打开相册 → 点那张图 → 编辑水印 → 保存 → 确认保存
```

6～7 步、有次数限制、必须离开取景器。工程现场一个测点往往只有十几秒的操作窗口，这条链路走不完。

本应用把链路压成：

```
按快门 → 面板自动弹出（第一格已聚焦、数字键盘已起）→ 输数值 → 回车 · 回车 · 回车
```

全程不离开取景器，照片在后台完成水印烧录和入库。

| | 今日水印相机 | 图数相机 |
|---|---|---|
| 操作步数 | 6～7 次点击 | 2 次点击 + 键盘输入 |
| 是否离开取景器 | 是 | 否 |
| 单张耗时 | 20～40 秒 | 实测 2.8 秒一轮 |
| 字段能否自定义 | 模板内改文字 | 完全自定义「分类 + 标签 + 数值 + 单位」 |
| 次数限制 | 有 | 无 |

## 2. 水印的结构

水印默认显示在照片**左下角**，半透明黑底，分类行用浅绿强调，数值行加粗；位置可在编辑照片时调整，颜色、大小和字段格式可自定义。

```
┌──────────────────────────────────────┐
│ ① 常驻层   项目名称: …航道整治工程    │  拍前可改，取景器顶部横条直接点
│            标段: XX合同段             │
│ ② 分类层   【基平台】                    │  一句说清这组数属于哪种结构
│ ③ 速录层   测点桩号: K0+350              │  拍后弹窗只填这一层，加粗显示
│            深度: 1000 mm                │
│            平整度（水平）: 3.1 / 3.2 mm   │  一个标签可带多个读数
│            宽度: 2000 mm                │
│ ④ 系统层   2026-10-29 19:18:07           │  按快门那一刻冻结，自动写入
└──────────────────────────────────────┘
```

第 ②③ 层是产品核心：分类决定字段集合，字段「标签 + 数值 + 单位」全部可自定义。

## 3. 数据分类

按现场实际的分部位组织，一套模板下可以有多个分类，每个分类有自己的一组字段。
拍之前先在取景页第三行选分类，速录面板就只显示该分类的字段；面板里也能直接换，**已经填过的值不会丢**。

出厂预置「航道整治」模板，五个分类照现场表格配好：

| 分类 | 字段（默认单位） |
|---|---|
| 基平台 | 测点桩号、深度(mm)、平整度（水平）(mm)×2、平整度（垂直）(mm)×2、宽度(mm) |
| 顶平台 | 同上 |
| 坡面 | 测点桩号、深度(mm)、平整度（水平）×2、平整度（垂直）×2 |
| 钢丝网格 | 砂垫层(cm)、网格铺石层(cm) |
| 排水沟/截流沟 | 测点桩号、上口宽(mm)、左侧深(mm)、右侧深(mm)、下底宽(mm) |

- **多值字段**：平整度每个方向记 2 个读数，面板里排成两个输入框（①②），存储用 `/` 连接，水印渲染成 `3.1 / 3.2`。
- 分类、字段、单位、值个数、哪个字段是桩号，都能在「模板 → 编辑模板」里改。

## 4. 桩号自动递增

工程上桩号是连续推进的，手打每一站既慢又容易错。规则：

| 情况 | 行为 |
|---|---|
| 第一次 | 空着，手填（如 `K0+350`） |
| GPS 位移 < 1.5 m | 判定还在同一测点（只是换了个部位拍），沿用上次桩号 |
| GPS 位移 1.5～300 m | **按位移反算推进**（Haversine 距离，取整到米） |
| 无定位 / 位移 > 300 m | 按模板里配的步长推进（默认 20 m），避免 GPS 跳点带歪 |

- 桩号解析很宽容：`K0+350` / `k0+350` / `0+350` / `350` / `K0+350.5` 都能认。
- 格式化统一补三位：`350 → K0+350`，`1050 → K1+050`，`12350 → K12+350`。
- 面板顶部会写明本次是怎么推出来的（`桩号已按 GPS 位移 +12.4 m 推算` / `GPS 位移不可用，按步长 +20 m 推算`）。
- 预填的桩号是**全选状态**，不同意就直接打字覆盖。
- 桩号状态**按模板存、所有分类共用**：在 K0+350 拍完基平台再拍顶平台，桩号不会跳。
- 保存后 toast 会回显桩号（`已保存 · K0+362`），不用回列表确认。
- 没有桩号字段的分类（钢丝网格）不参与递增，也不会污染状态。

## 5. 镜头拉近推远（推拉条）

快门上方是一条**推拉变焦轨道**，不是点一下就跳的按钮：

- **按住往左右推**，画面连续跟着变，松手停住。
- **点轨道上的档位刻度**（1× / 2× / 4× / 8× / 上限）直接吸过去，戴手套也能点准。
- **双指捏合**仍然可用，捏的时候轨道上的手柄会跟着走，两套操作同一个倍率。
- 轨道用**对数映射**：1×→2×、2×→4×、4×→8× 在轨道上占的宽度一样，手感均匀。线性映射会让 1×→2× 只占 1/9 行程、2×→10× 占 8/9，完全没法微调。
- 档位由设备能力生成（这台 vivo 从 0.7× 到 10×），上限自动收口；刻度文字互撞时自动避让。
- 倍率实时显示在气泡里，退出重进会恢复上次用的倍率。

## 6. 横竖拍摄，控件位置固定

v1.7 将相机界面方向与照片方向分开处理。界面固定竖向，横拿手机时快门、缩放条不换位置，取景和录入期间也不再切换布局。

照片使用 `OrientationEventListener` 获取物理朝向，独立设置 `ImageCapture.targetRotation`；方向切换增加 10° 缓冲，避免斜握时反复跳变。快门按下时确定照片方向，保存时仍按 EXIF 方向解码后绘制水印。

水印尺寸继续按图片短边计算，因此横、竖照片的字号比例一致。方向实现参考 [CameraX 官方旋转指南](https://developer.android.com/media/camera/camerax/orientation-rotation)。

## 7. 记录、删除与 CSV 导出

每拍一张，除照片外还落一条记录（`files/records.jsonl`，一行一条 JSON）。取景页右上角「记录」进入：

- 列表按时间倒序，显示时间、分类、桩号、各字段值、位移。
- **单击**进「改这张照片」，**长按**出菜单（编辑数值 / 查看照片 / 删除）。
- **删除**时问一句「只删记录（照片留在相册）」还是「记录和照片一起删」——有人只要表，有人连废片一起清。
- **清空**一次清掉全部，同样问照片留不留。
- 选择“仅 CSV”会导出当前筛选结果，表中包含以下字段。

```
序号,拍摄时间,模板,分类,桩号,桩号(米),位移(米),GPS纬度,GPS经度,定位地址,照片文件,来源,
项目名称,标段,测量区域,深度(mm),平整度（水平）1(mm),平整度（水平）2(mm),…,下底宽(mm)
1,2026-10-29 19:31:55,航道整治,基平台,K0+350,350.0,,,,,MC_20261029_193155_172.jpg,拍摄,…
3,2026-10-29 19:33:00,航道整治,排水沟/截流沟,K0+390,390.0,,,,,MC_20261029_193300_367.jpg,导入,…,452,369,503,416
```

要点：

- **列是并集**：不同分类的字段各自成列，某行不属于该分类就留空，`分类` 列负责区分。
- **多值字段拆成多列**（`平整度（水平）1` / `2`），方便直接在 Excel 里做统计。
- **`来源` 列**区分现场拍的（`拍摄`）和从相册补进来的（`导入`）——后补的图拍摄时间可能是几天前，混在一张表里容易看错。
- **带 UTF-8 BOM**，Excel 打开中文不乱码（这是国内用 CSV 最常见的坑）。
- 同时落到两个地方：`Download/图数相机/`（数据线可直接拷）和应用私有目录（用于分享）。
- 导完可以直接「分享」给微信/邮件，走 FileProvider，不需要存储权限。

## 8. 导入已有照片

现场常见的情况：先用别的相机或微信拍了一堆，回头才想起来要加水印。记录页右上角「导入」可以把相册里已有的照片拉进来。

- 走系统的**照片选择器**（Photo Picker），**不需要任何存储权限**。用户只把选中那几张授权给应用，比"读取整个相册"干净得多。
- 一次最多 20 张（`MAX_IMPORT`）。解码 + 重编码是同步的，堆太多会卡很久。
- 每张走的是**和拍摄完全一样的一条流水线**：留无水印基底 → 渲染 → 进相册 → 落记录。

区别只有两点：

1. **数值留空**。导入时不知道这组数是哪个测点的，所以记录里按分类把字段骨架预置好、值全空着，进编辑页逐个填就行（下面第 9 节）。
2. **不写桩号递增基准**。这张可能是几天前在别的桩号拍的，拿它当基准会把整条链带偏。

拍摄时间按这个顺序取：**EXIF 原始时间 > MediaStore `DATE_TAKEN` > 文件修改时间 > 现在**。顺序不能反——微信转发的图 `DATE_TAKEN` 往往是转发时刻，EXIF 才是真拍的。

导入的原图会**重新编码成标准 JPEG** 存进 `originals/`，方向已经拍平、不带 EXIF Orientation。直接存原始字节也行，但 HEIC/PNG 进来后文件名还是 `.jpg`，后面解码会踩坑。

外部图片的方向标记比相机复杂得多：除了 `ROTATE_90/180/270`，还有 `FLIP_HORIZONTAL`（自拍镜像）、`FLIP_VERTICAL`、`TRANSPOSE`、`TRANSVERSE`。只处理前三种的话，镜像的图会整个倒过来。`ImageLoader` 现在把 8 种全铺平了。

顺带修了一个内存隐患：降采样原来判断的是"降一半之后是否还超标"，5000×4000 的图算 5000/2=2500 小于上限就原样解出来，占 80MB。相机自己拍的 12MP 没事，导入单反/高像素照片很容易在这里 OOM。现在按"降完还超不超"判断。

## 9. 改一张已经拍好的照片

现场手抖填错一个数、或者水印压在关键部位上，以前只能删了重拍。现在可以改：

- 从记录页点进去，**上方是从原图重绘的成片预览**，改一个数就重画一次（240ms 防抖）。
- 每个数值行都能改，右上角 ✕ 删掉这一行，「＋ 添加一行数值」补一行。
- 常驻信息（项目名称/标段/测量区域）也能在这里改。
- **水印位置**：3×3 九宫格点哪放哪（左上/上中/右上/左中/居中/…/右下），**字号**0.7×～1.8× 可调。
- 保存后覆盖相册里同名的那张，文件名不变，记录同步更新。

### 为什么拍的时候要留一份原图

水印是**画进像素**的，一旦烧上去就抠不下来。想改数值，必须有没水印的那张。

所以从 v1.3 起每次拍摄会把相机输出的原图另存一份到 `files/originals/`（不进相册）。改数值时从原图重画，**反复编辑也不会累积画质损失**——每次都从同一张干净的原图出发。

代价是每张照片占两份空间，所以 `OriginalStore` 设了 800MB 上限，超了从最老的开始清（当前正在编辑的那张会被保护）。原图只服务于编辑，删记录时一并删掉。

老记录（v1.2 及更早）没有原图，记录页会标「无可编辑原图」，点进去能看、能删，但改不了数值——硬改会让新旧水印叠在一起。

## 10. 速度是怎么抠出来的

1. **快门时刻冻结时间**：`capturedAt` 在 `takePicture()` 前取一次，用户填多久都不影响水印时间。
2. **解码与填表并行**：照片一落盘就把解码扔到 `ioExecutor`，用户敲键盘的两三秒里照片已经解好了，保存时直接取 `Future`，省掉 300～600ms。
3. **弹窗即聚焦**：`showForm()` 里 `post { requestFocus(); showSoftInput() }`，不用户再点一下。
4. **`setSelectAllOnFocus(true)`**：连续测点时直接输新值就把旧值覆盖，不用先删。
5. **回车即跳格**：`IME_ACTION_NEXT` 手动接管焦点，末格 `IME_ACTION_DONE` 直接保存。物理回车在 `setOnKeyListener` 里消费掉（`setOnEditorActionListener` 挡不住 TextView 内部的默认焦点前进，会跳两格）。
6. **沿用上次数值**：连续测点数值往往相近，一键填满空格，只改变化的那一格；桩号不会被旧值覆盖。
7. **桩号自动预填**：多数情况下第一格直接回车跳过，一轮少 5～8 次按键。

## 12. 使用流程

1. 首次打开：授予相机 + 定位权限（定位被拒也能拍，只是水印没有坐标行）。
2. 顶部第一行选模板，第三行选分类（基平台/顶平台/坡面/钢丝网格/排水沟）。
3. 第二行点常驻字段（项目名称/标段/测量区域）直接填，填一次一直保留。
4. 需要拉近就推底部的变焦条，或者双指捏合。
5. 按快门 → 面板弹出 → 桩号已预填，回车跳过 → 输数值 → 末格回车直接保存。
   - 横着拍的时候屏幕会先转成竖屏再弹面板，录完自动转回去。
6. 填错了不用重拍：回「记录」页点这条 → 改数值 / 挪水印 → 保存，相册里那张跟着更新。
7. 相册里本来就有照片要加水印：回「记录」页点「导入」，选图 → 自动加水印入库 → 点条目补填数值。
8. 现场拍完，回「记录」页 → 导出记录 → 选择 ZIP 或 CSV。

### 本轮（v1.4）实机发现并修掉的问题

1. **横屏拍出来是竖幅、水印跟着歪**。根因是 `screenOrientation="portrait"` 把 `display.rotation` 钉死在 0，CameraX 于是永远按竖屏补 90°。改成 `fullSensor` + `configChanges` + 在 `onConfigurationChanged` 里手动更新 `targetRotation`。详见第 6 节。
2. **横向成片的字号比竖向大 33%**。缩放基准原来取图片宽度，横向图短边是高，算出来就偏大。改成按短边，两种方向完全一致。
3. **横屏下速录面板被键盘压得只剩一格**。横屏可用 360dp 减去软键盘只剩一百多 dp。改成横屏拍完先转竖屏再弹面板，录完放回跟随物理方向。
4. **横屏布局把快门推到屏幕右侧 190dp 处**。变焦条和按钮挤在同一行，三个 Space 一分就偏了。改成变焦条独占一行、按钮行三等分。
5. **点回已填的输入框，新输入会接在旧值后面**（`K1+200` → `K1+200K1+500`，`850` → `850900`）。
   `setSelectAllOnFocus`、`setOnFocusChangeListener` 都在 `ACTION_DOWN` 触发，紧接着的 `ACTION_UP` 会把光标重新定位、把全选取消；`setOnClickListener` 更彻底——`EditText` 的触摸由内部 `Editor` 消费，根本不会调。最后改为自己监听触摸，在 `ACTION_UP` 之后如果落成"光标态"就补一次全选。速录面板和编辑页都改了。
6. **降采样漏掉中间尺寸**。5000×4000 的图算 `5000/2=2500` 小于上限就原样解出来，占 80MB。相机自己拍的 12MP 没事，导入高像素照片很容易 OOM。改成按"降完还超不超"判断。
7. **导入的镜像图会整个倒过来**。原解码只处理 `ROTATE_90/180/270`，自拍镜像常见的 `FLIP_HORIZONTAL` 等另外 4 种被忽略。现在 8 种全支持。

### 上一轮（v1.3）修掉的问题

8. **清空对话框的选项整个不见了**。`setMessage` 和 `setItems` 同时设，正文区只放得下一样。改成列表式选择。
9. **变焦刻度文字打架**。8× 和 10× 在对数轴上贴太近。改成两端优先保留、中间让路。
10. **生成图标的白色既当背景又当图形**。按亮度一刀切会把刻度环内侧打成透明。改成从四角灌水只吃连通背景。

### 上一轮（v1.2）修掉的问题

11. **无 GPS 时桩号状态不落地**。改成只有桩号就存，坐标可为空。
12. **面板内切换分类后打字没反应**。重建输入框后要把焦点和键盘还给第一格。

### 关于 Lint 的 36 条 warning

全部是刻意的，没有一条需要修：

- `LockedOrientationActivity` / `DiscouragedApi`（5 条）：模板、记录、编辑页锁竖屏——都是表单，转屏重建会把没保存的输入冲掉。取景页用的是 `fullSensor`，Lint 也按"锁定方向"算。

## 15. 已知限制

- 一版一拍：保存期间快门置灰，暂不支持连拍排队。渲染约 300～800ms。
- 水印可拖动到照片内的任意可用位置，字号与内容长度会影响可移动范围。
- **改数值必须有原图**。v1.2 及更早拍的记录没留原图，只能看和删，改不了。
- 原图占双倍空间。上限 800MB，超了从最老的开始清；被清掉的原图对应记录也会变成"改不了"。
- 无防篡改能力。时间取设备系统时间，不接授时中心，也不做验真码——内部记录够用，对外举证不够。
- GPS 精度取决于设备；室内/地下拿不到坐标，此时桩号退回步长推算，水印也会省略坐标行。
- 分类内的"桩号"字段全模板共用一条链，不支持按分类各自独立递增。
- 记录只在手机本地，没有云端同步和多人协同。
- 记录与照片按文件名关联，在系统相册里手动改名/删除后，记录页点条目会提示"照片已不在相册"。
- 编辑页返回、取消和导航返回均检查未保存修改，支持保存、继续编辑或放弃。系统杀进程时仍不提供草稿恢复。
- **导入的图没有地址**。EXIF 里只有经纬度，反查地址要联网、还要按张发请求，所以导入时地址留空，水印会少一行地址。坐标有就写。
- **导入的图不改原始文件**。应用只是读出来复制一份到自己的目录，相册里你原来那张不会被改动，删记录也不会删它。
- 相机界面固定竖向；横拿手机时界面文字不会整体转成横屏，照片方向仍随方向传感器变化。
- 横屏 + 超长数值会把水印块撑高，极端情况下可能压住画面主体。位置和字号都能在编辑页调。
